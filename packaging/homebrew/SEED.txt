Copy refresh.go, refresh_test.go, test-cask.rb, LICENSE and .github/workflows/refresh.yml
into the dedicated Dunky13/homebrew-agent-job-queue repository. Use a signed,
DCO-signed-off initial commit on its default branch named tap. Do not copy SEED.txt.
The refresh program is self-contained and uses only Go's standard library. It
needs no module downloads, Python installation, uv environment, or fetched app
source. Source tests verify that its trusted cask template matches the app's
renderer. Run its isolated tests with: go test -p 2 refresh.go refresh_test.go
The app source repository's protected main branch remains independent.

The refresh workflow reads only the known public app repository. It selects the
highest numbered published build with a strict JSON manifest, downloads the known
app ZIP asset, verifies its SHA256, regenerates Ruby using the trusted local
template, checks it through the real Homebrew DSL, and only then creates a signed
GitHub API commit on tap. It never evaluates released Ruby. No PAT is needed.
The GitHub Actions token is scoped to contents:write in this dedicated repository.
The returned commit is checked for a Verified signature and matching author DCO.
Expected-head compare-and-swap and current-build checks prevent stale updates.

The source release workflow dispatches expected_tag and expected_commit through
a GitHub App with Actions write access to the tap only, waits for the exact run,
and independently verifies the resulting signed cask commit. Configure its
Client ID variable and private-key secret using docs/homebrew-delivery.md in the
source repository. Missing credentials fail delivery explicitly.

Scheduled refresh runs every 15 minutes as recovery; GitHub may delay or drop it.
Owners can run Refresh generated tap manually after a source release. A missing
published release or inconsistent current cask fails visibly. Exact current
metadata is revalidated before no-op. Newer published descendants may supersede
older requests; downgrades and conflicting identities are rejected.

PRs targeting tap run read-only refresh regressions, separately from publication.
Keep all copied trusted helpers byte-identical to the
reviewed source revision. The source delivery job checks parity before dispatch,
so merge a companion tooling PR before the corresponding source PR. Do not
advertise installation until a first validated refresh has published a cask.

After publication the fully qualified command selects/trusts only this cask:
  brew install --cask dunky13/agent-job-queue/agent-job-queue
Homebrew 7 explicitly trusts a fully qualified item on install; no whole-tap trust
or quarantine bypass is required. New main releases are Developer ID signed and
notarized; the trusted cask retains quarantine for macOS assessment. Publication
must pass the source release signing, notarization and Gatekeeper checks.
Historical ad hoc builds and their casks remain unchanged until a newer release.
The refresh helper compares historical Ruby only as bounded data and never runs
it. Local development packages can remain ad hoc signed. Offline first launch
of the standalone Go executables has not been verified.

The cask is a plain app cask: its only artifacts are the app and a quit-only
uninstall. Homebrew just places Agent Queue.app; it runs no installer script,
flight step, binary link or setup command. Opening the app from Applications
performs setup itself (registers its bundle-owned services and writes the
agent-heavy and agent-remote wrappers to ~/.local/bin). macOS retains control
of any required background-service approval in Login Items settings.

The real DSL fixtures cover the exact artifact contract, protected staging,
quarantine retention, upgrade rollback and uninstall without touching private
runtime files. Synthetic fixtures use a data-only app that is never executed;
notarized release acceptance executes the real Apple verifiers against the
extracted release app (AGENT_QUEUE_TEST_NOTARIZED_APP) and its Gatekeeper
assessment, and registers no Service Management jobs.

Homebrew uninstall asks a running app to quit, then removes the app. Services,
jobs, history and credentials are removed only by the app's explicit
ownership-checked service-removal command, which the cask caveats name and
which must run before deleting the app. No destructive zap action is supplied.

A tap that still holds metadata for a release built with the earlier installer
wrapper is accepted as the current state, checked against its public release and
archive checksum, and compared as data against the frozen trusted managed-app
template or its bounded published cask. Neither legacy template is executed or
republished. It is replaced by the first app ZIP release. A latest public
release that still uses the installer asset name fails visibly instead of
publishing a cask for it.
