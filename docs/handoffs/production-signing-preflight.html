Changes¶ ↑

The credential wrapper now queries the full and valid code-signing identity inventories in its own temporary Keychain before invoking the child. Selection requires exactly the configured full name or case-insensitive fingerprint, validity, Developer ID Application type and the expected team. The child receives the resolved uppercase SHA-1. An absent, invalid, ambiguous, wrong-team or inconsistent selection fails closed without choosing another certificate.

Diagnostics print fixed classifications and counts, plus the selected public fingerprint and team only for a ready identity. Raw inventory names, command errors, passwords and private keys are not printed. A failed child refreshes the inventory classification and keeps its original exit code. Host search lists, default Keychains, trust settings and signing requirements are unchanged.

The workflow also retains an initial s00 snapshot after state verification and before credential setup. The snapshot permits recovery from a first import or preparation failure without losing the reviewed installer. If a stage already has prepared bytes without a durable ID, its existing ambiguity guard still refuses resubmission. Missing state, expired submission checkpoints, corruption, provenance mismatch and rejected submissions remain failures. There is no fallback from a known expired submission checkpoint to the initial snapshot.

This closes the observed pre-sign recovery gap and makes the next hosted identity failure distinguishable. It does not claim that the original hosted signing error is already fixed. The next approved main run must provide that evidence before production publication can be certified. The failed build's workflow cannot acquire these changes through a rerun of its old commit.

Validation contract¶ ↑

Tests first reproduced the missing initial-checkpoint behavior and the lack of identity preflight at the actual wrapper seam. Coverage includes exact names, both fingerprint cases, missing/invalid/ambiguous/wrong-team/type identities, malformed or failed inventory queries, no alternate valid-certificate fallback, safe diagnostics, child exit-code preservation and all existing credential custody, process-group cleanup and cancellation checks.

Checkpoint integration restores the initial state into a new attempt and makes exactly its first submission using private tools. Existing tests still reject unknown upload outcomes, prior prepared state without an ID and missing state. Workflow tests require the initial immutable upload before any signing stage; an expired submission checkpoint cannot fall back to s00.

Local mocked recovery tests, real credential-import/signing checks, exact-head hosted CI, independent review and post-merge production proof must be reported separately. No operator installation is authorized. The standing signing guide contains the recovery commands and trust boundaries. A standalone HTML version accompanies this handoff.
