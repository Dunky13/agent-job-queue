Evidence and uncertainty¶ ↑

Source inspection passes the selected fingerprint and private Keychain to codesign. The matching inventory staying valid does not prove successful private-key access. Earlier local Developer ID checks also had the same certificate in the default identity search, so they did not prove independence from that existing identity. The local machine runs macOS 27.0.1; the failed hosted runner used macOS 15.7.9, image 20260907.0337.1.

A unique synthetic identity in an unlisted private Keychain signed successfully locally without trust or search-list changes. Thus missing default-list visibility alone did not reproduce the failure on the local OS. Installed codesign documentation says certificate-chain lookup can consult the normal search list even with an explicit Keychain. This is a boundary to investigate, not evidence that a missing intermediate caused this failure. No trust, credentials, default Keychain or search list was changed to get green.

Change¶ ↑

Fixed operation markers distinguish credential configuration, installer restoration, each known helper/app/installer signing step and its verification, and DMG signing/verification. They emit begin and success/failure with the original status; they do not emit command arguments, paths or credential selectors. Reusing prepared bytes does not repeat preparation or markers.

Wrapped shell functions explicitly return failing command statuses so Bash's conditional-call behavior cannot hide configuration or restoration failures. Signing, verification requirements, credential cleanup and upload ambiguity guards remain enabled. No search-list or trust workaround is added.

A native macOS test generates a unique short-lived synthetic signing identity in an owned disposable Keychain. It confirms that the identity is absent from default lookup, signs a copied system executable with the explicit Keychain and fingerprint, verifies all architecture signatures, and verifies that the embedded certificate has that exact fingerprint. It checks unchanged host Keychain settings and deletes its owned Keychain. It requires no production credentials, trust changes, Apple upload or target execution. This gives both hosted macOS architectures a test independent of the operator's identities; it cannot certify a Developer ID trust chain or notarization.

Regression tests at the real prepare seam inject failures before signing, during restoration, for each payload signing target, and during verification. They require the correct marker and original status, no next operation, no prepared archive or stage record, and no submission. Ordered success and prepared-state reuse are covered separately.
